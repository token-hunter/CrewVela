# 领域文档规则

## 布局与读取

采用 single-context 布局：

- 术语表位于根目录 `GLOSSARY.md`。
- 架构决策记录位于 `docs/adr/`。

探索代码前，读取已有术语表和与本次任务相关的 ADR。
文件不存在时继续工作，无需预先补齐。
通过 domain-modeling，在术语或设计决策得到确认后按需创建。

如果以后出现 `GLOSSARY-MAP.md`，按其指引读取相关领域的术语表。

## 使用术语

需求、任务、分析和测试中涉及领域概念时，
采用术语表定义的名称与含义。

遇到缺失术语时，先核对项目实际用法；
确有歧义再通过 domain-modeling 澄清。

## 处理决策冲突

方案与已有 ADR 冲突时，明确指出对应 ADR、冲突内容，
以及建议重新讨论该决策的理由。
