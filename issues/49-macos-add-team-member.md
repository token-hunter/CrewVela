# Mac 协作中心新增与编辑成员窗口

## 需求

维护者在 Mac 最新 main 构建中点击新增成员和编辑成员均无反应。限定修复共用成员编辑窗口，保留已有保存校验和键盘交互。

## 复现与范围

- Windows Chromium 正常设置页可打开；没有 Mac 原生运行环境，尚未确认 Mac 现场的唯一根因。
- 实际组件嵌入滚动/绘制裁切容器后，成员弹窗仍挂在容器内，关闭按钮被裁切并无法命中。
- 改为将成员编辑窗口通过 portal 挂到 body，并在设置页之上显示，避免依赖父容器的 fixed/overflow 绘制行为。
- 不修改全局 Modal、不修改成员后台操作、不推送或更新 Release。

## 验证

- 修复前：裁切容器中成员窗口位于父容器内部，关闭按钮的指针命中为 false；修复后窗口在父容器外，指针命中为 true，显示层级为 200。
- 通过 CUA 实际运行 Chromium：新增保存、编辑保存、空名称校验、保存失败保留草稿、取消、关闭按钮、Escape、Tab 循环及关闭后焦点返回均通过。
- 完整设置页预览：成员窗口挂载于设置页之外；Escape 仅关闭成员窗口，保留设置页。
- 为保持焦点返回，使用 Modal 的 initialFocusRef 指向名称框，替代会提前抢走来源焦点的 autoFocus。
- 新增隔离 IPC fixture 和可在 Chromium/WebKit 重放的 UI 回归脚本；本次通过 CUA 执行等价交互，独立 Playwright 脚本仅作语法检查，未宣称已执行该脚本或 WebKit。
- Node：434 项通过、1 项既有跳过；类型检查与 Vite 构建通过，保留既有大分块警告。
- 没有 Mac 原生现场日志或运行环境，尚不能认定此显示层问题就是维护者现场的唯一根因；等待 Mac 实机复核。
- 维护者于 2026-11-10 授权本任务源码提交；本次不推送、不重新打包 EXE/DMG、不更新 Release。原有用户数据未读取或修改。
