# 共享记忆跨实例更新与失败步骤定位

Status: ready-for-human

## 原因

新版 EXE 下载与校验完成后，更新拒绝之前实例留下的独立服务。当前进程没有其 Child 句柄；实际服务为当前用户、CrewVela 托管目录及匹配的数据/配置启动参数。磁盘 server.pid 已过期，与实际监听进程不同。错误又被错误放到末尾检查步骤。

## 实现与范围

- Windows 从指定回环监听端口取得唯一 PID，核验当前用户 SID、程序路径、创建时间及完整启动参数，保留 OS 进程句柄；不依靠 PID 文件授权停止。
- 下载前先核验可接管性，下载后再次取得/核验句柄，停止前复核同一身份；只停止指定服务，随后保持完整冷快照、迁移及回退流程。外部程序/其他数据目录不停止。
- 修复步骤间错误归属，优先标记下一待执行步骤；进度顶部显示完整失败摘要。
- macOS 仍保留原有未核验旧进程拒绝接管行为，本轮不宣称 Mac 原生跨实例接管已适配。

## 验证

- 旧代码隔离重启场景先失败：服务存活但 Child 丢失时拒绝更新。
- Windows 共享记忆 Rust 59 项通过、6 项 opt-in 默认跳过；真实官方包跨实例升级测试另行显式通过。测试让旧服务保活、丢弃本实例的 Child，并写入过期 PID；正确定位服务、核验停止、迁移、注入两种失败后恢复、再次升级均通过，MCP/Hooks/项目标记及测试记忆保留。
- IPv4/IPv6 监听进程定位、当前用户身份及命令行核验通过；错误数据目录、多余参数、与目标不符的活进程不接管。步骤间错误正确归入下一阶段，末尾检查保持等待。
- Node 472 通过、1 既有跳过；两套 Chrome 界面回归通过（IPC 模拟），失败摘要可见。
- 不停止实际用户服务、不升级原数据；原生 EXE 重建后交用户复测。macOS 跨实例接管未适配。本轮未提交或推送。
