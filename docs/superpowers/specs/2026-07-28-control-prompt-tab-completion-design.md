# 总控输入框 Tab 补全设计

> 为总控输入框增加可发现、不会误覆盖内容的示例指令补全。
> 日期：2026-07-28

## 1. 目标

用户聚焦总控输入框时，可以看到一条示例指令，并通过一次 `Tab` 将其填入输入框，无需手动输入。

## 2. 交互

- 默认补全文本为：`打开 1 个 GLM 和 2 个 Kimi 会话`。
- 输入框为空且获得焦点时，以幽灵文本展示完整建议，并显示 `Tab 补全` 提示。
- 当前输入是建议文本的前缀时，幽灵文本只展示尚未输入的剩余部分。
- 有可见补全建议时按 `Tab`：阻止本次默认焦点切换，将完整建议写入输入框，光标移动到末尾。
- 没有可见补全建议时按 `Tab`：不拦截浏览器默认行为，继续用于键盘焦点导航。
- 补全只填入文本，不发送；仍由 `Enter` 发送。
- 点击幽灵建议或 `Tab 补全` 提示，与按 `Tab` 行为一致。

## 3. 边界

- 不覆盖与默认建议不匹配的已有输入。
- `Enter`、`Shift+Enter`、`Ctrl+Shift+Enter` 的现有行为保持不变。
- 输入框禁用或总控正在执行时不提供补全。
- 本轮只实现一条固定建议，不引入历史记录、AI 推荐或多候选列表。

## 4. 实现范围

- 在 `ControlSidebar` 中集中定义默认建议文本。
- 根据 `draft` 计算当前是否可补全以及剩余提示文本。
- 在输入框内容层上方增加不接管编辑的幽灵文本展示层，并提供可点击的补全入口。
- 在现有 `handleKeyDown` 中优先处理符合条件的 `Tab`，其余快捷键逻辑保持原样。
- 增加必要的浅色、深色主题样式及无障碍标签。

## 5. 验收

1. 空输入框按 `Tab` 后填入完整建议，不发送。
2. 输入 `打开 1 个` 后按 `Tab`，补全为完整建议。
3. 输入不匹配内容后按 `Tab`，焦点正常移动，不修改内容。
4. 点击补全提示可填入完整建议。
5. 原有发送、换行和发送至全部快捷键不受影响。
