# 模型统一分配

设置 → 模型设置采用统一分配表，可按项目、范围和名称/模型筛选。点击一行的「编辑」，保存或取消后再切换筛选，避免丢失未保存草稿。

## 配置与实际执行

- CLI 默认模型支持 Claude Code、Codex、Kimi Code、Pi、OpenCode。它们保存在 `runtime-model-defaults.json`，不修改 CLI 原有的全局配置文件。
- Claude Code 可使用现有模型服务连接或本机配置。其它 Agent 沿用自己的本机账号和 CLI 配置；本页不将 Claude 的服务连接转换为其它协议或声明账号已认证。
- 项目成员的模型保留在原 `ma_agents.model` 字段；连接单独保存在 `ma_model_connections`，同一 SQLite 事务保存，不重建成员、任务和会话。
- 执行优先级为：会话启动覆盖 → 成员覆盖 → Agent 默认 → CLI 本机配置。显式从某个服务连接新建的 Claude 会话继续优先使用该服务的配置。
- 保存默认不会改变已运行的会话。后续启动/恢复、或项目成员下一次需要重新启动 Runtime 时使用新配置；繁忙终端不会因模型变化被自动中断。
- 团队消息直接唤醒成员时读取该成员配置及目标会话覆盖，不会退回普通 CLI 默认；成员被删除、停用或 Runtime 已变化时拒绝使用旧关联启动。
- 会话表显示启动参数记录，CLI 内 `/model` 等操作后的实际模型请以原会话为准。旧会话缺少启动记录时明确显示“未记录”，不将当前默认反推为历史实际模型。
- 只有未绑定 PTY 的待启动/已停止 CLI 会话可在本页编辑启动覆盖。运行中的终端、原生聊天及专用适配器未开放的切换请在原会话中操作。

## 兼容与恢复

旧 Claude 成员的 `model` 字段曾可保存服务 ID 或名称，仍按历史规则解析。编辑这种条目时会展示拆分后的实际连接和模型，保存为类型化连接＋模型，避免把服务名误存为模型 ID。

「恢复继承」清除所选范围的覆盖。成员恢复会保留名称、职责、Runtime、任务和会话关系。过期编辑和运行状态变化会拒绝保存，失败保留草稿。

模型候选来自现有配置和启动记录，不代表服务端一定支持或账号已获授权；也可以输入 CLI 支持的模型 ID。模型配置文件、API Key 和模型实际可用性分别验证。

## 总控与连接管理

项目中的总控角色仍是现有成员，按成员真实 Runtime 执行。自然语言任务解析器仍使用 Claude Code，现会继承 Claude Code 的默认连接和模型，不在本次改变其协议实现。

「管理连接」保留现有服务编辑、隐藏/删除、排序、额度和恢复默认功能；可通过「返回模型分配」回到表格。

## 验证边界

Rust 回归验证持久化、SQL 原子更新、优先级、旧数据、并发冲突、连接与 CLI 参数；浏览器使用正式组件和隔离 IPC 验证操作流程。Mock 和构建不代表真实账号授权、模型请求成功或 macOS 原生验收。
