# 团队协作会话

右侧“多智能体”采用一个项目、一条公共对话。项目、成员、目标、讨论轮次和任务结果都保留真实身份，不再根据自然语言暗中切换到普通总控或全局广播。

## 使用

1. 选择或创建协作项目，在“管理项目与成员”中配置已有Runtime成员。Agent继续使用本地CLI账号与模型配置。
2. 选择具体成员。支持多选、全选和明确的`@成员名`；同名成员用身份后缀区分。未知或停用目标不会自动变成全员广播。
3. “讨论”按成员依次收集观点、相互回应，再由实际成员汇总；默认一次回应遍次、整轮10分钟，服务端有硬上限。
4. “执行项目”先生成可审阅分工。确认卡展示负责人、写入范围、验收命令、依赖和审查人；点击“按此分工执行”才创建工程任务并请求现有调度器启动。
5. 对话中可人工插话，停止后续安排；暂停讨论与任务详情里的暂停项目分开。未确认停止时保留冻结状态，核对原进程后才允许新轮。
6. “任务”打开任务详情，查看真实负责人、验收要求、尝试记录、输出和日志；可以打开原会话或既有协作工作台处理审批及交付。

## 执行与事实边界

- 公共对话只使用本会话显式公开的消息，不导入成员私信、其他项目历史或模型思考内容。
- 每条成员发言关联讨论轮次、回复对象、Task/Run和真实成员。空输出、失败、超时和未确认停止均显示实际状态，不用固定话术冒充Agent。
- 用户消息的“completed”只表示保存成功；成员“回复结束”只表示本轮回复结束；工程任务“验收通过”由原任务/审查/验收状态决定。
- “分工已确认”表示计划已落库或应用；具体任务仍可能排队、失败或等待审批，不等同工程已启动/完成。
- 重复发送及计划确认使用持久请求身份。网络响应丢失时可使用原编号核对，明确回执出现后不再重复投递。
- 关闭或隐藏面板不会自动批准交付，也不会成为讨论后台运行的必要条件。应用重启后不盲目重放未确认的旧轮次，需要核对或显式新轮。
- 写代码复用独立Worktree、文件范围、依赖、Review和人工验收；工程目录需要满足现有Git工作树前提。创建项目元数据不等于自动初始化Git仓库。

## Runtime支持

受限讨论只为后端明确列出的Runtime启用，不支持者在界面说明，不能仅靠“请不要写文件”的提示词冒充只读保障。当前实现通过ACP强制只读且不注入额外MCP提供Claude Code/Codex讨论；Pi以禁用工具、扩展、MCP的独立讨论方式接入。实际安装、登录、账户额度仍是各CLI自己的前置条件。工程任务继续沿用原有Runtime适配范围。

## 验证与待验收

界面通过真实React+隔离IPC进行深浅色、窄面板、具体成员选择、去重、项目切换、人工插话、计划确认及错误恢复检查。后端通过隔离存储与可注入执行器检查持久化、隐私、调度和停止范围；这些不替代真实模型验收。
