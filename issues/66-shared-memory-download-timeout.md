# 共享记忆安装包下载超时与重试

Status: ready-for-human

## 现象与原因

原生 EXE 更新在“下载并校验新版服务”阶段报 response body 超时，备份和替换尚未开始。代码使用 120 秒请求总超时，没有中断重试和下载进度。隔离 HTTP 服务器在正文中途断开，生产下载函数测试复现立即失败。

## 实现

- 官方下载使用连接、读取停滞及整个下载过程三层时限，最大 3 次尝试，每次刷新 GitHub 跳转地址并从头下载。
- 接入首次安装及服务更新的现有进度事件，显示已下载大小、百分比、重试及本地包替代入口。
- 保留官方元数据、SHA256、大小上限、解包和可执行能力检查；校验不符直接失败，不使用镜像或降低 TLS 校验。
- 下载成功前不暂停旧服务或改变记忆数据；错误不回传带签名的临时下载 URL。

## 验证

- 原下载函数中途断开测试先失败，再修复通过。另验证持续慢速传输、读取停滞最多三次、刷新跳转地址、百分比更新，以及 SHA256/声明大小不符时不重试、不安装。
- 共享记忆 Rust 56 通过、6 opt-in 默认跳过。其中官方在线下载/校验/隔离安装额外显式执行通过（全程 133.88 秒），官方 2.6.0→3.4.5 真实隔离迁移、策略保护、故障回退和重试另行通过（18.77 秒）。
- Node 472 通过、1 既有跳过；两套真实 Chrome 界面回归通过（IPC 模拟），覆盖进度刷新与失败重试。模拟快照按真实 IPC 克隆，避免同一对象引用掩盖进度刷新。
- 不升级真实用户服务，不提交、推送或更新 GitHub Release。构建独立 EXE 供用户原生复测；Mac 原生下载/更新与当前用户网络路径仍需实际验证。
