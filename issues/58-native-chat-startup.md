# 安装版原生 Chat 启动失败

Status: ready-for-human

## 根因与复现

- 浏览器 MCP 的 ESM 启动入口比较未解析链接的 argv 路径和 Node 已解析的模块路径。品牌兼容目录为 junction/symlink 时，两者不相等，进程以 0 退出且没有协议响应。
- Codex 安装版经 npx 查找适配器时，npm 将绝对 Node 路径拼入 shell；含空格的安装目录被拆分，ACP 初始化前退出。
- 新增实际子进程回归：普通目录握手通过，迁移链接目录在原代码下失败；换回旧 Codex npx 构造后，空格与元字符路径执行测试失败。

## 修复

- 浏览器桥接两侧比较实际文件路径；保留作为库导入时不启动服务的语义，不关闭 MCP，不删除兼容目录。
- npx 仅执行固定启动文本，Node 查找目录显式继承；wrapper 路径通过环境传递，避免把空格、中文和 shell 元字符当作命令。不改变版本锁定、账号、模型及权限设置。

- 实际浏览器 MCP 经测试 junction 发现 25 个工具；实际 Claude ACP 初始化通过，未调用模型。
