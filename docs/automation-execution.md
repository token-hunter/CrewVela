# 自动化计划与执行记录

自动化使用本地 Agent CLI 配置。计划负责后续触发，每一轮执行有独立编号和消息目标，两者状态分别显示。

## 状态与操作

- 已入队只证明消息进入持久队列；已提交只证明文本/回车写入；已接收只证明对应运行时确认收件。
- 项目任务按该消息对应的 `cli-message-<messageId>` 和实际 Run 更新执行、等待、结束或失败状态，保留消息、任务、Run 与原会话标识。
- 普通终端只有同时取得本消息的实际提交和匹配结束回执，才记录回复结束。当前可关联的 Claude hook 路径支持这一证据；没有可靠回传的其他 CLI 不推测成功。已投递但一分钟仍缺少回传时显示“结果未确认”，之后取得匹配结果仍可更新。
- “已完成”表示对应执行或回复结束，不代替用户要求的项目验收。项目工程验收继续使用既有任务/审查流程。
- 每日任务完成一轮后仍启用。一次性触发结束、达到次数上限、计划暂停和最近执行结果分别呈现。手动执行/重试不改变下次计划时间，也不消耗计划触发次数。
- 立即执行与失败重试使用持久请求编号。响应丢失后保留同一编号，重复请求不会再次派发；只有已确认失败或取消的记录可以重试。
- 暂停后续计划不停止本轮。“停止本轮”只撤销精确匹配且尚未写入的队列消息，或取消尚未启动的对应项目消息任务，或向该任务的实际 Run 请求停止。请求停止不等于停止成功，退出未确认时仍保留待核对状态。
- 已进入普通共享 CLI 且缺少可靠归属时，页面拒绝强停并提示打开原会话处理，避免结束其他工作。多目标中有无法安全定位的目标时，不冒充全批停止成功。
- “已核对原会话”需要明确确认原任务不再执行。它清除待核对状态，实际结果仍未知，不计成功，也不重发。仍有活动项目任务时不能用此入口跳过停止确认。

## 持久化与恢复

执行登记及目标标识先于消息入队落盘。旧派发记录和重启时未结束记录标记为结果未知；重启遗留的自动化消息暂停自动重放，普通非自动化消息保持原队列行为。

默认“上一轮未结束则跳过”包含结果不明的执行。允许重叠时仍限制每个计划最多20个活动/未确认记录，避免无限积累。历史优先保留活动记录；手动请求收据在历史裁剪后继续保留，每个计划最多4096个，达到上限时明确拒绝新请求，不回收旧编号造成重放。

文件版本4兼容旧计划和周期/事件规则；旧失败保持失败，旧“派发成功”不转换成任务完成。读写失败会返回错误，调度异常在主界面提示。

## 验证边界

隔离测试覆盖持久幂等、旧记录迁移、重启不重放、实际提交/结束身份匹配、人工接管、项目 Run 关联、计划独立状态、安全停止范围、过滤及深浅色/窄窗口。测试不调用真实模型或用户现有自动化；模型账号、额度及真实多 CLI 双向互聊仍需后续验收。
